# 🧭 Travel DSS — система поддержки принятия решений для путешествий

**Travel DSS** — исследовательский прототип системы поддержки принятия решений (СППР), который помогает выбрать туристическое направление и составить персонализированный маршрут с учётом интересов, бюджета, продолжительности поездки и ограничений по времени.

Приложение объединяет методы многокритериального анализа, оценки риска, рекомендательных систем, базы знаний, прогнозирования погоды и математической оптимизации в **одном интерфейсе Streamlit**.

## 🚀 Быстрый запуск

### 1. Требования

- **Python 3.10 или новее** (рекомендуется Python 3.11).
- Git — для клонирования репозитория.
- Подключение к интернету понадобится для первоначальной установки зависимостей.

### 2. Скачайте проект

```bash
git clone https://github.com/Annawhq/travel-dds.git
cd travel-dds
```

Если Git не установлен, можно скачать архив репозитория через **Code → Download ZIP** на GitHub и распаковать его.

### 3. Создайте виртуальное окружение

```bash
python -m venv .venv
```

**Windows (PowerShell):**

```powershell
.venv\Scripts\Activate.ps1
```

**Windows (командная строка cmd):**

```bat
.venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
source .venv/bin/activate
```

### 4. Установите зависимости

```bash
python -m pip install -r requirements.txt
```

Приложению также нужен Streamlit. Если он ещё не указан в `requirements.txt` или не установлен в окружении, выполните:

```bash
python -m pip install streamlit
```

Для решения оптимизационных задач используется **PuLP 2.9.0** с решателем **CBC**. Если решатель недоступен в конкретной среде, расчёт маршрутов может не выполняться; остальные аналитические функции при этом могут работать.

### 5. Запустите приложение

Из **корневой папки проекта** выполните:

```bash
python -m streamlit run app.py
```

Откройте адрес **http://localhost:8501** в браузере, если страница не открылась автоматически.

Для остановки приложения нажмите `Ctrl+C` в терминале.

> **Важно:** запускайте команду из корня репозитория, чтобы приложение могло найти папки `src/` и `data/`.

## 🧩 Возможности системы

- **Выбор направления из 15 городов России.** Рейтинг учитывает предпочтения пользователя, веса критериев, отношение к риску и бюджетные ограничения.
- **Настройка профиля туриста.** Город отправления, интересы, поездка с детьми, первое посещение, предполагаемая погода, отношение к риску и пользовательские веса критериев.
- **Расчёт бюджета на 1–3 дня.** Учебная оценка билетов, проживания, посещений, питания, городского транспорта и резерва; проверка общего бюджета и отдельных лимитов.
- **Рекомендации достопримечательностей.** Персональное ранжирование с учётом тематики, привлекательности, стоимости, погоды и экспертных правил.
- **Планирование маршрутов по четырём городам:** Казань, Нижний Новгород, Калининград и Сочи. Оптимизатор учитывает часы работы объектов, длительность посещений, переходы, бюджет и приёмы пищи.
- **Погодная аналитика для Казани.** Прогноз среднемесячной температуры, 80%-й интервал неопределённости и исторические вероятности погодных сценариев.
- **Представление результата.** Расписание посещений по дням, схематическая карта, итоговая смета и выгрузка плана в `.txt`.

## 🖥️ Как пользоваться

1. В панели слева укажите город отправления, продолжительность путешествия (**1–3 дня**), бюджет, интересы и другие предпочтения.
2. Нажмите **«Пересчитать рекомендации»** — система покажет рейтинг городов и оценку финансовой доступности.
3. Выберите направление и нажмите **«Выбрать направление и показать детали»**. Можно выбрать не только лидера рейтинга.
4. Изучите предварительную смету, персональный список достопримечательностей и, для Казани, погодный прогноз.
5. Для одного из четырёх городов с каталогом объектов нажмите **«Построить персональный маршрут»**.
6. Посмотрите расписание, схематическую карту и итоговые расходы. При необходимости скачайте **текстовый план путешествия**.

При изменении профиля нажмите кнопку пересчёта: предыдущий маршрут будет сброшен, чтобы не отображать устаревшее решение. Оптимизация выполняется по отдельному запросу и в интерактивном режиме имеет ограничение по времени.

### Пример сценария

Для знакомства с системой можно выбрать **отправление из Москвы**, **2 дня**, **общий бюджет 30 000 ₽**, **лимит на билеты 15 000 ₽**, **лимит на объекты и питание 3 000 ₽**, интерес **«Культура и история»** и нейтральное отношение к риску. Затем открыть Казань или Нижний Новгород и построить маршрут.

## 🧠 Методы и компоненты

| Компонент | Назначение | Реализация |
|---|---|---|
| Многокритериальный анализ (AHP) | Оценка городов по взвешенным критериям | `src/multicriteria/` |
| Анализ риска и неопределённости | Погодные и ценовые сценарии, критерии Вальда, Байеса, Гурвица и др. | `src/uncertainty/` |
| Оптимизация маршрута (MILP) | Выбор объектов и построение расписания с ограничениями | `src/optimization/` |
| База знаний | Продукционные правила, учёт интересов и состава путешественников | `src/knowledge/` |
| Прогнозирование погоды | Месячный прогноз и исторические погодные сценарии для Казани | `src/forecast/` |
| Рекомендательный модуль | Персональные рейтинги городов и объектов, бюджетные фильтры | `src/recommendations/` |
| Управляющий сервис | Объединение расчётов в единый сценарий принятия решения | `src/dss/service.py` |
| Пользовательский интерфейс | Веб-приложение на Streamlit | `app.py` |

│   └── processed/           # подготовленные данные для аналитики

## ✅ Тестирование

Команды запускаются **из корня проекта** после установки зависимостей.

**Рекомендательный модуль:**

```bash
python -m unittest discover -s tests -p "test_recommendations.py" -v
```

**Интеграция погодной модели:**

```bash
python -m unittest discover -s tests -p "test_weather_integration.py" -v
```

**Построение маршрутов для разных городов:**

```bash
python tests/check_city_routes.py
```

**Поездки на 1–3 дня и семейные сценарии:**

```bash
python tests/check_trip_durations.py
```

Последние две проверки запускают оптимизационный решатель и могут потребовать больше времени, чем модульные тесты.

## 📊 Данные и ограничения

**Travel DSS — исследовательский прототип, а не сервис бронирования.** При интерпретации результатов необходимо учитывать следующее:

- Оценки направлений и стоимость поездок в `data/test/` **учебные**. Они не являются актуальными предложениями перевозчиков или гостиниц.
- В каталоге содержатся **225 базовых двухдневных смет** для пар городов; для поездок на 1 и 3 дня выполняется модельный пересчёт. В сумме доступны **675 расчётных комбинаций** «направление — продолжительность».
- Для маршрутов подготовлены каталоги **Казани (40 объектов), Нижнего Новгорода (32), Калининграда (32) и Сочи (31)**. Часть координат, стоимости, расписаний, рейтингов и продолжительности посещения получена из открытых источников или задана экспертно/синтетически. Для дополнительных городов сведения об источниках и статусе проверки представлены в `data/raw/catalog_sources.csv`.
- Маршруты рассчитываются в пределах туристического дня **10:00–20:00**; начальная точка условно представляет место проживания. Расстояния и время перемещения приближённые, линии на карте **не являются реальными навигационными маршрутами**.
- Прогнозная модель разработана **только для Казани**. Прогноз относится к **средней температуре месяца**, а вероятности осадков — к историческим сценариям, не к погоде на конкретные даты.
- При сложных ограничениях оптимизатор может не найти допустимый маршрут (`Infeasible`) или не завершить поиск за выделенное время. Отсутствие найденного решения за лимит времени не доказывает его невозможность.
- Система не учитывает актуальную загруженность объектов, изменения расписаний по праздничным дням и наличие свободных билетов и гостиниц.
